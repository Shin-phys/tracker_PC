# マーカー形状のベンチマーク

追跡マーカーの形を変えると位置精度がどう変わるかを、**このアプリが実際に使っている
照合アルゴリズムそのもの**で測るための一式です。アプリのビルドには関わりません
（`npm run build` からも GitHub Actions からも参照されない、オフラインの検証コードです）。

## なぜ必要だったか

「白い丸シールより十字のほうが精度が上がるのでは」という問いに、
実測なしで答えると当てずっぽうになります。実動画では真の位置が分からないので、
真値の分かっている合成画像を作って誤差を直接測りました。

結果として、事前の予想は 2 つ外れました。

- 白黒4分割の円が最良だろうと考えていましたが、実際は**十字のほうが 2 倍良い**。
- 方眼紙の背景では十字が紛れやすいだろうと考えていましたが、実際は**十字が最良**で、
  そこで破綻するのは**白い丸**のほうでした（150 回中 100 回）。

そして、いちばん効くのは形ではありませんでした。**枠の中身が物体と一緒に動くかどうか**が、
形状の差より一桁大きく効きます。

## 測っていること

| 指標 | 意味 |
|---|---|
| `rms` | 位置推定の誤差 [px]。サブピクセル精度そのもの |
| `fail_rate` | 1px 以上外した割合。そもそも捕まえ損ねた割合 |
| `score` | `TM_CCOEFF_NORMED` の一致度。`lostThreshold`（既定 0.45）との距離 |
| `margin` | 最良ピーク − 離れた場所の 2 番目のピーク。小さいほど軌跡が飛びやすい |

## 実行

```bash
pip install numpy opencv-python-headless reportlab
python3 bench.py main      # 7 形状 × 8 条件 × 150 回     （約 4.5 分）
python3 bench.py bias      # ピクセルロッキングの S 字      （約 1 分）
python3 roi_sweep.py       # 枠の倍率 × 物体の有無          （約 4 分）
python3 body_test.py       # 物体の表面が単色か模様ありか    （約 2 分）
python3 verify.py          # 測定系そのものの点検           （約 2 分）
python3 marker_sheet.py    # 印刷用マーカーシート（A4・実寸）
```

結果は `results_*.json` に落ちます。レポート（HTML）は
`python3 previews.py && python3 build_report.py` でチャートの断片を作ってから、
`report_template.html` に差し込んで組み立てます。

## 測定系の作り方

10 倍のスーパーサンプリング座標系で描き、面積平均（`INTER_AREA`）で縮小しています。
実際のカメラの画素は面積積分なので、これが物理的に正しい標本化です。
マーカーは 10 倍座標の整数位置に置くので、1× でのサブピクセル位置は必ず 1/10 の倍数になり、
真値は丸めではなく厳密に決まります。

`engine.py` の `quadratic_peak` / `_parabolic` は `src/utils/tracker.ts` の
同名の処理を 1 対 1 で移したものです。**`tracker.ts` のサブピクセル補間を変更したら、
ここも合わせて直してください。** 合わせ忘れると、このベンチマークは
「実装していないアルゴリズム」を測ることになります。

## 点検結果（`verify.py`）

- **ヌルテスト** — ノイズ 0・無地背景・変位 0 で、誤差は 7 形状すべて 1×10⁻⁶ px 以下
- **推定量の偏り** — ノイズ 0 で残る誤差（ピクセルロッキング）は 0.008〜0.012 px。
  標準条件の誤差 0.06〜0.25 px の 5〜25 分の 1 なので、結論を左右しない
- **理論との整合** — ボケを強くするとピクセルロッキングは σ0.4 の 0.02 px から
  σ1.5 以上で 0.003 px 以下まで単調に減る（相関ピークが広がるほど 3×3 の
  2 次曲面フィットが成り立つ、という予測どおり）
- **再現性** — 乱数の種を 3 通り変えても、上位 4 種と最下位の順位は変わらない

## 扱っていないこと

合成画像なので、レンズの歪み、ローリングシャッター、**動画コーデックの圧縮ノイズ**、
印刷のにじみ、シールの反射は入っていません。とくに圧縮は、細い線を持つマーカー
（細い十字）に対して合成ノイズより不利に働く可能性があります。
細い十字ではなく太い十字を推している理由の一つです。
