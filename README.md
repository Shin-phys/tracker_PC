# MotionTrace Pro Ver.2（PC 版）

動画内の最大 5 個の物体を自動追跡し、位置・速度・相対距離を取り出す Web アプリです。
物理実験のマーカー追跡を想定しています。ブラウザだけで動き、動画はサーバへ送られません。

スマートフォン専用版は [tracker_mobile](https://github.com/Shin-phys/tracker_mobile) にあります。
追跡・校正・平滑化のアルゴリズム（`src/utils/`）は両者で同一なので、同じ動画からは同じ数値が出ます。

## 起動

```bash
npm install
npm run dev
```

ビルドは `npm run build`（`tsc` の型チェック → `vite build`、出力は `dist/`）。

## 画面構成

```
┌───────────────────────┬──────────────┐
│ Header                                │
├───────────────────────┼──────────────┤
│                       │ ControlPanel │ 対象・校正・追跡設定
│  VideoCanvas          ├──────────────┤
│  （映像＋軌跡＋操作）   │ DataPanel    │ グラフ・計測値・フィルタ・CSV
└───────────────────────┴──────────────┘
```

## 追跡

1. 動画を読み込む
2. 追跡したいマーカーをドラッグで囲む（**20px 以上**、できれば 30px 前後）
3. 再生する

小さすぎる枠は画面上のどこにでも一致してしまい、軌跡が暴走します。囲めない大きさのときは、
先に拡大してから囲んでください。

追跡が外れたら、一時停止して「修正」ツールで点を正しい位置へドラッグします。
その位置でトラッカーを作り直すので、そこから追跡を続けられます。記録済みデータも書き換わります。

画面外に出た物体は `exited` として追尾を打ち切り、軌跡もそこで終端します。

## スケール校正

3 モードあります。

- **平面（四隅）** — 基準の四角形の四隅を 左上 → 右上 → 右下 → 左下 の順にクリック。
  射影変換で遠近を補正するので、**斜めから撮った映像でも正しい実寸**が出ます。
- **2点間** — 既知の長さを 2 点で指定。光軸が運動面に垂直なときだけ正しい値になります。
- **追跡枠の幅** — 枠の幅を基準にする簡易モード。

置いた点は掴んでドラッグ、または矢印キーで 1px ずつ動かせます。
斜めから撮った映像では必ず平面校正を使ってください。2点間校正では遠近の分がそのまま誤差になります。

## グラフ概形確認モード

右ペイン `DataPanel` の一番上。**縦軸（x / y / vx / vy / 速さ）** と **横軸（t / x / vx）** を
別々に選ぶ方式で、x-t, y-t, vx-t, vy-t, y-x, vy-vx をすべて含みます。
定番の組み合わせはプリセットのチップから 1 クリック。右上の「拡大」で全画面表示（Esc で閉じる）。

これは飾りではなく **その場で計測が使い物になるか判断するための道具**です。

- **グラフをクリックするとその時刻へ動画がシークします**（再生中なら自動で止まります）。
  vx-t / vy-t に鋭いスパイクが出ていたらそこで追跡が飛んでいるので、クリックして飛び、
  映像の「修正」ツールで直す、という流れになります。
- **カーソルを載せるだけで最寄りの点の t と両軸の値**を読めます。クリックせずスパイクの大きさを確かめられます。
- **y-x と vy-vx は等縮尺**で描きます。縦横の縮尺が違うと放物線が放物線に見えず、形の判断ができません。
  等縮尺のときは右上に「等縮尺」と出ます。
- **見失ったフレームでは線が切れます**。つないで描くと、追跡が飛んだ区間まで滑らかな曲線に見えて
  データが正しいと誤解するためです。
- 物体が複数あるときは色分けして重ね描きし、下の凡例をクリックすると個別に表示を切り替えられます。

描いているのは **平滑化フィルタ適用後の値＝CSV に出るのと同じ数字**なので、
フィルタの効き具合をその場で確認する用途にも使えます。

なお **a-t（加速度）は用意していません**。2 回微分はノイズが支配的になり、かえって誤った印象を与えるためです。

## 平滑化と速度

位置を微分して速度を出すとノイズが Δt で割られて増幅されます。微分の前に平滑化するのが定石です。

- **Butterworth 零位相**（既定・推奨）— 残差の自己相関（Durbin-Watson 統計量）が最小になる
  遮断周波数を 0.5Hz からナイキスト周波数まで走査して自動選択します（Kinovea と同じ方式）。
  X と Y で別々に選びます。
- **Savitzky-Golay** — ウィンドウ幅と多項式次数を指定する方式。

速度は平滑化後の座標の **中心差分**で求めます。前方差分より 1/2 フレーム分の位相ずれがなく、ノイズにも強い方式です。

## データの取り出し

`DataPanel` の **CSV ダウンロード**（BOM 付き UTF-8 / Excel 対応）。

出力列: `Timestamp` / 各物体の `X(px), Y(px), X, Y, Vx, Vy, Speed, Score, Lost, Manual` / 物体間距離

`Score` はマッチングスコアです。追跡の信頼度を後から検証できます。
`Manual` は手動で位置を直したフレームの印です。

## 精度を出すコツ

- 枠は 20px 以上、できれば 30px 前後
- 斜めから撮った映像は必ず平面（四隅）校正
- 取りこぼすときは再生速度を 0.5× に落とす
- 追跡が飛んでいないかは、必ず **vx-t / vy-t のグラフで確認**する

## 技術

React 18 + TypeScript + Vite / OpenCV.js（`@techstark/opencv-js`）によるテンプレートマッチング。
サブピクセル補間は相関マップのピーク近傍 3×3 に 2 次曲面を最小二乗フィットして求めます
（実測でガタつきの 2 階差分 RMS が 1.06px → 0.35px）。

フレーム処理は `requestVideoFrameCallback` を使い、提示された実フレームごとに 1 回だけ行います。
時刻は動画本来の `mediaTime` を使うので、画面の描画周期に引きずられません。
