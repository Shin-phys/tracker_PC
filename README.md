# MotionTrace Pro Ver.2（PC 版）

動画内の最大 5 個の物体を自動追跡し、位置・速度・相対距離を取り出す Web アプリです。
物理実験のマーカー追跡を想定しています。ブラウザだけで動き、動画はサーバへ送られません。

スマートフォン専用版は [tracker_mobile](https://github.com/Shin-phys/tracker_mobile) にあります。
追跡・校正・平滑化のアルゴリズム（`src/utils/`）は両者で同一なので、同じ動画からは同じ数値が出ます。

## 起動

```bash
npm install
npm run dev
```

ビルドは `npm run build`（`tsc` の型チェック → `vite build`、出力は `dist/`）。

## 画面構成

```
┌───────────────────────┬──────────────┐
│ Header                                │
├───────────────────────┼──────────────┤
│                       │ ControlPanel │ 対象・校正・追跡設定
│  VideoCanvas          ├──────────────┤
│  （映像＋軌跡＋操作）   │ DataPanel    │ グラフ・計測値・フィルタ・CSV
└───────────────────────┴──────────────┘
```

## 追跡（自動）

1. 動画を読み込む
2. 追跡したいマーカーをドラッグで囲む（**20px 以上**、できれば 30px 前後）
3. 再生する

小さすぎる枠は画面上のどこにでも一致してしまい、軌跡が暴走します。囲めない大きさのときは、
先に拡大してから囲んでください。

追跡が外れたら、一時停止して「修正」ツールで点を正しい位置へドラッグします。
その位置でトラッカーを作り直すので、そこから追跡を続けられます。記録済みデータも書き換わります。
修正できたかどうかは画面上部の帯に出ます。

画面外に出た物体は `exited` として追尾を打ち切り、軌跡もそこで終端します。

## 追跡（手動記録）

自動追跡が使えない対象（変形する物体、低コントラスト、遮蔽が多い）はコマごとに手で指します。
映像下の **「手動記録」** から入ります。

1. コマごとに対象をクリックする
2. その コマの全対象を打つと、自動で設定コマ数だけ進む
3. 動画を 1 周すれば終わり

- 打つ順番は `Obj1 → Obj2 → …` と案内されます。**物体チップを押せば順番を飛ばして指名**できます
  （1 回限り。打つと自動の順番へ戻ります）
- **取り消し**で 1 点ずつ遡れます
- 記録は自動追跡と同じデータに入り、CSV の `Manual` 列で区別できます。
  **自動で 7 割追って、追えない区間だけ手動で埋める**という使い方ができます

### コマ送り幅が精度を決めます

加速度は位置を 2 回微分して出すので、クリックのぶれが 1/Δt² で拡大されます。
**細かく打つほど良い、ではありません。** 合成データ（自由落下・240fps 撮影・クリック精度 ±0.6px・40 点）
で重力加速度を推定したときのばらつきです。

| 何コマおき | 実時間の間隔 | ばらつき |
|---|---|---|
| 1 コマ | 4.2 ms | 40.7 % |
| 2 コマ | 8.3 ms | 11.4 % |
| 4 コマ | 16.7 ms | 2.7 % |
| **8 コマ** | **33.3 ms** | **0.7 %** |
| 16 コマ | 66.7 ms | 0.2 % |

偏りは出ない（平均は常に真値）ので、問題はばらつきだけです。目安として **実時間で 30〜50ms** 空けます。
スライダーには実時間の間隔が併記され、短すぎる設定は警告色になります。
撮影 fps から推奨値が自動で入ります（通常 30fps なら 1 コマ、240fps スローなら 10 コマ）。

## スケール校正

3 モードあります。

- **平面（四隅）** — 基準の四角形の四隅を 左上 → 右上 → 右下 → 左下 の順にクリック。
  射影変換で遠近を補正するので、**斜めから撮った映像でも正しい実寸**が出ます。
- **2点間** — 既知の長さを 2 点で指定。光軸が運動面に垂直なときだけ正しい値になります。
- **追跡枠の幅** — 枠の幅を基準にする簡易モード。

置いた点は掴んでドラッグ、または矢印キーで 1px ずつ動かせます。
斜めから撮った映像では必ず平面校正を使ってください。2点間校正では遠近の分がそのまま誤差になります。

### 原点

映像下の **「原点」** で、座標の原点にしたい位置をクリックできます（斜面の始点、レールの目盛り 0 など）。
CSV の `X, Y` がその点からの値になるので、表計算側でオフセットを引く手間がなくなります。

未指定なら従来どおり画像の左下（`Y軸を上向き` が OFF なら左上）が原点です。
平面校正では射影変換したあとに平行移動するので、遠近がかかっていても正しく効きます。
動画を読み込み直すと解除されます（画像座標なので別の動画では意味を持たないため）。

## 時間軸（スロー動画）

スマホの 240fps スローモーションは **30fps のファイルとして書き出される**ことが多く、
その場合ファイル上の 8 秒が実際には 1 秒です。動画から読める時刻はファイル上の時刻なので、
そのままでは速度が 1/8、加速度が 1/64 になります。

`ControlPanel` の「フレームレートと時間軸」で **撮影 fps**（スマホの撮影設定の数字）を指定してください。

```
実時間 = ファイル上の時刻 × (ファイルの fps ÷ 撮影 fps)
```

ファイルの fps は自動計測されるので、入力するのは撮影 fps だけです。
未指定なら等倍で、通常の動画の挙動は変わりません。
換算が効いているときは、ヘッダー・グラフ全画面・CSV の説明にその旨が出ます。

> **注意**: 以前の版にあった「FPS の手入力」は廃止しました。
> あの値はコマ送りの刻みにしか使われず、自動計測より正確になることがないためです。
> 240 などを手入力すると、コマ送りが 1 回で 1 コマ進まなくなる不具合の原因にもなっていました。

## グラフ概形確認モード

右ペイン `DataPanel` の一番上。**縦軸（x / y / vx / vy / 速さ）** と **横軸（t / x / vx）** を
別々に選ぶ方式で、x-t, y-t, vx-t, vy-t, y-x, vy-vx をすべて含みます。
定番の組み合わせはプリセットのチップから 1 クリック。右上の「拡大」で全画面表示（Esc で閉じる）。

これは飾りではなく **その場で計測が使い物になるか判断するための道具**です。

- **グラフをクリックするとその時刻へ動画がシークします**（再生中なら自動で止まります）。
  vx-t / vy-t に鋭いスパイクが出ていたらそこで追跡が飛んでいるので、クリックして飛び、
  映像の「修正」ツールで直す、という流れになります。
- **カーソルを載せるだけで最寄りの点の t と両軸の値**を読めます。クリックせずスパイクの大きさを確かめられます。
- **y-x と vy-vx は等縮尺**で描きます。縦横の縮尺が違うと放物線が放物線に見えず、形の判断ができません。
  等縮尺のときは右上に「等縮尺」と出ます。
- **見失ったフレームでは線が切れます**。つないで描くと、追跡が飛んだ区間まで滑らかな曲線に見えて
  データが正しいと誤解するためです。
- 物体が複数あるときは色分けして重ね描きし、下の凡例をクリックすると個別に表示を切り替えられます。

描いているのは **平滑化フィルタ適用後の値＝CSV に出るのと同じ数字**なので、
フィルタの効き具合をその場で確認する用途にも使えます。

**表示だけの平滑化トグル**（既定 OFF）を使うと、グラフの見た目からノイズを一段落とせます。
2 次 Savitzky-Golay なので放物線は鈍りません。位置を均し、速度も均した位置から計算し直します。
CSV には影響しません。ただし ON のあいだは追跡の飛びも均されて見えにくくなるので、
**スパイクを探すときは OFF にしてください**（ON のときは画面に注意書きが出ます）。

なお **a-t（加速度）は用意していません**。2 回微分はノイズが支配的になり、かえって誤った印象を与えるためです。

## 平滑化と速度

位置を微分して速度を出すとノイズが Δt で割られて増幅されます。微分の前に平滑化するのが定石です。

- **Butterworth 零位相**（既定・推奨）— 残差の自己相関（Durbin-Watson 統計量）が最小になる
  遮断周波数を 0.5Hz からナイキスト周波数まで走査して自動選択します（Kinovea と同じ方式）。
  X と Y で別々に選びます。
- **Savitzky-Golay** — ウィンドウ幅と多項式次数を指定する方式。

速度は平滑化後の座標の **中心差分**で求めます。前方差分より 1/2 フレーム分の位相ずれがなく、ノイズにも強い方式です。

### どちらを選ぶか

合成データ（自由落下）で速度カーブの点ごとの誤差を比べた結果です。

| 条件 | Butterworth 自動 | Savitzky-Golay 7点 |
|---|---|---|
| 手動記録 40 点（40ms 間隔） | **−57 %** | +131 % |
| 手動記録 20 点 | **−45 %** | +76 % |
| 自動追跡 30fps・200 点 | **−33 %** | +1335 % |
| 自動追跡 240fps・300 点 | **−77 %** | −47 % |

（フィルタ OFF を基準にした増減。マイナスが改善）

**Butterworth はどの条件でも改善します。** 遮断周波数をデータから決めるので、
サンプリング間隔に自動で追随するためです。手動記録のように点数が少ない場合も有効です。

**Savitzky-Golay は窓を「時間」で考える必要があります。** 同じ 7 点でも 240fps なら 29ms、
30fps なら 233ms を均すことになり、後者では運動そのものが削られます。
有効なのは窓が 20〜40ms 程度のときだけです。
UI には「この設定で均す時間」を ms で表示し、長すぎる場合は警告を出します。
迷うなら Butterworth を使ってください。

## データの取り出し

`DataPanel` の **CSV ダウンロード**（BOM 付き UTF-8 / Excel 対応）。

出力列: `Timestamp` / 各物体の `X(px), Y(px), X, Y, Vx, Vy, Speed, Score, Lost, Manual` / 物体間距離

`Score` はマッチングスコアです。追跡の信頼度を後から検証できます。
`Manual` は手動で位置を直したフレームの印です。

## 精度を出すコツ

- 枠は 20px 以上、できれば 30px 前後
- 斜めから撮った映像は必ず平面（四隅）校正
- 取りこぼすときは再生速度を 0.5× に落とす
- 追跡が飛んでいないかは、必ず **vx-t / vy-t のグラフで確認**する
- スロー動画では **撮影 fps を必ず設定**する（忘れると加速度が 1/64 になります）
- 手動記録では **細かく打ちすぎない**（実時間で 30〜50ms の間隔を空ける）

## 技術

React 18 + TypeScript + Vite / OpenCV.js（`@techstark/opencv-js`）によるテンプレートマッチング。
サブピクセル補間は相関マップのピーク近傍 3×3 に 2 次曲面を最小二乗フィットして求めます
（実測でガタつきの 2 階差分 RMS が 1.06px → 0.35px）。

フレーム処理は `requestVideoFrameCallback` を使い、提示された実フレームごとに 1 回だけ行います。
時刻は動画本来の `mediaTime` を使うので、画面の描画周期に引きずられません。

コマ送りも同じ考え方です。`currentTime += 1/fps` で進めた「要求時刻」ではなく、
シーク後に **実際に表示されたフレームの `mediaTime` を読み直して**記録します。
これで fps の推定は「どのコマに着地するか」だけを決め、記録される時刻には影響しません。
fps を 20% 誤って推定していても、時刻の誤差は毎コマ自己修正されます（`src/utils/videoFrame.ts`）。

### スマホ版との共通コード

`src/utils/` と `src/types/` は [tracker_mobile](https://github.com/Shin-phys/tracker_mobile) と
1 行も違わないので、**この PC 版を正として同期**しています。

```bash
npm run sync:core        # スマホ版へコピー
npm run sync:core:check  # 差分があれば異常終了（コミット前の確認用）
```

共通コードを直すときは必ずこちら（PC 版）を編集してください。
同期先は隣のフォルダを中身で自動判別します（`TRACKER_MOBILE_DIR` で明示指定も可）。
UI（`src/components/`）は両者で別物なので共有していません。
